# BRM-Net 结构化剪枝验证报告

日期：2026-06-25

## 1. 验证目标

本轮验证不再使用连续门控均值代替压缩率，而是检查完整闭环：

1. BN 后 Hard-Concrete 通道门控；
2. 面向 Params/MACs 的可微资源预算；
3. 按目标资源投影为硬通道结构；
4. 导出不含门控层的紧凑模型；
5. 对紧凑模型微调并重新评估。

数据协议固定为 Houston2013 official split，训练集 2,832，测试集 12,197；
三档实验均使用 train seed 0、20 个结构训练 epoch、10 个紧凑模型微调 epoch。

| 90% | 89.94% | 91.90% | 87.13% | 89.22% | 86.08% | 86.42% |

## 3. 验收判断

- **实际预算命中：通过。** 三档 MACs 误差均小于 0.2 个百分点。
- **结构单调性：通过。** MACs、Params 和总体宽度随预算单调增加。
- **真实紧凑模型：通过。** 导出模型不包含门控参数，硬模型和紧凑模型资源统计一致。
- **CPU 导出等价：通过。** 单元测试中最大绝对误差小于 `1e-5`。
- **CUDA 数值等价：基本通过但需如实披露。** 最大绝对误差为
  `1.76e-4` 至 `1.95e-3`，相对 L2 误差约 `1.06e-5` 至 `1.52e-5`。
  差异来自裁剪后卷积计算形状改变导致的 CUDA 累加顺序差异，不是权重映射错误。
- **65% 相对 90% 精度差不超过 2 pp：未通过。** 实际下降 `2.40 pp`。

因此，本轮证明了“可学习预算 -> 硬结构 -> 紧凑模型 -> 实际资源统计”的工程与实验闭环，
但当前单 seed 结果还不足以直接启动完整三随机种子主实验。

## 4. 关键发现

1. 固定 `0.5` 阈值无法产生目标硬结构，因为各层概率分布集中且层间尺度不同。
   当前采用全局概率断点搜索，使硬结构的实际 MACs 最接近目标预算。
2. 随机 Hard-Concrete 采样在小数据、BatchNorm 场景下训练不稳定。
   当前默认确定性连续门控训练，导出阶段再做硬投影。
3. 紧凑模型直接导出后精度明显下降，10 epoch 微调是闭环中的必要步骤。
4. 65% 和 80% 的 OA 接近，说明低预算瓶颈不只是总计算量，还与被删除通道的位置有关。
5. Head 第二层 64 个通道在三档中均全部保留，当前资源分配主要发生在编码器和融合接口。

## 5. 下一步优先级

### P0：低预算稳定性

- 保存 compact 微调期间的最佳 checkpoint，而不是固定使用最后一个 epoch；
- 增加逐层最低宽度或敏感度约束，避免全局阈值过度裁剪关键层；
- 在 65%/80% 上进行 3 次短重复，判断 `2.40 pp` 差距是否属于单 seed 波动。

### P1：缺失模态最低闭环

- 接入 availability mask 和 masked softmax；
- 训练阶段加入 modality dropout；
- 对 MQE 增加可解释质量监督；
- 目标是显著提升 `main_only/aux_only`，而不是继续堆叠复杂生成模块。

### P2：论文级工作量

- 将已验证的结构化预算机制迁移到服务器 ResNet 类双分支主干；
- 在更大主干上报告 Params、MACs、延迟和显存；
- 将当前 0.467M BRM-Net 保留为机制验证与消融模型。
